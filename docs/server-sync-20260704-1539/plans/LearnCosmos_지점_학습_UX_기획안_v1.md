## 1. 문서 목적

이 문서는 LearnCosmos의 코스별 학습하기 화면에서 실제 학습 행동이 일어나는 `지점` 단위 UX를 정의한다.

메뉴 기획안 v1은 전체 IA와 메뉴 위치를 다루고, 이 문서는 지점 안에서 학습자가 콘텐츠를 어떻게 관찰하고, 목표와 스킬을 찾고, 반복하고, 결과물을 남기며, 완료 여부를 판단하는지를 상세화한다.

핵심 목적은 다음과 같다.

```text
학습 콘텐츠를 단순히 소비하지 않고,
목표·스킬·반복·기록·결과물·자기평가로 소화하게 한다.
```

## 2. 코스별 학습하기와 지점 학습 UX의 관계

`코스별 학습하기`는 코스, 즉 행성 안의 지역과 지점 구조를 트리로 보여주는 학습 진입 화면이다.

기본 트리 구조는 다음과 같다.

```text
행성 / 코스
├─ 지역 / 리슨
│  ├─ 지점
│  ├─ 지점
│  └─ 지점
└─ 지역 / 리슨
   └─ 지점
```

하위지역은 필수 계층이 아니다. 학습 구조가 복잡한 경우에만 선택적으로 사용한다.

```text
행성 / 코스
├─ 지역 / 리슨
│  ├─ 하위지역 / 하위리슨
│  │  ├─ 지점
│  │  └─ 지점
│  └─ 지점
```

따라서 코스별 학습하기 화면은 다음 두 구조를 모두 지원해야 한다.

1. 행성 → 지역 → 지점
2. 행성 → 지역 → 하위지역 → 지점

## 3. 지점 유형

지점은 실제 학습 행동이 일어나는 단위다.

LearnCosmos에서 학습 콘텐츠를 다루는 지점은 크게 탐험지점과 연구지점으로 나눈다.

```text
지점
├─ 탐험지점
│  ├─ 크리에이터 학습 콘텐츠
│  └─ 외부 학습 콘텐츠
│     ├─ YouTube
│     ├─ 네이버 블로그
│     ├─ 논문자료
│     └─ 기타 웹 자료
└─ 연구지점
   └─ 사용자가 직접 정리한 학습 콘텐츠
```

### 3.1 크리에이터 학습 콘텐츠

```text
유형: 탐험지점
출처: 크리에이터 콘텐츠
```

크리에이터가 만든 학습 콘텐츠는 단순 자료가 아니라, 목표물 예시, 필요한 스킬 후보, 반복 가이드, 결과물 기준이 포함될 수 있는 학습경험 설계 콘텐츠다.

노출 예시:

```text
탐험지점 · 크리에이터
콘텐츠: 블로그 글쓰기 입문 1단계
크리에이터: 글쓰기 코치 루나
피드백 가능
```

크리에이터 콘텐츠인 경우, 조건에 따라 `크리에이터 피드백` 기능을 노출한다.

### 3.2 외부 학습 콘텐츠

```text
유형: 탐험지점
출처: 외부 콘텐츠
```

YouTube, 네이버 블로그, 논문, 웹 문서 등 외부 자료를 연결한다.

LearnCosmos는 외부 콘텐츠 자체를 소유하거나 판매하지 않고, 외부 자료를 목표·스킬·반복·기록·결과물·자기평가로 바꾸는 학습 도구를 제공한다.

노출 예시:

```text
탐험지점 · YouTube
콘텐츠: 파이썬 CSV 읽기 튜토리얼
[외부에서 열기]
```

### 3.3 사용자가 직접 정리한 학습 콘텐츠

```text
유형: 연구지점
출처: 사용자 직접 입력
```

사용자가 직접 학습할 내용을 입력하거나 정리한 자료를 다룬다.

예시는 다음과 같다.

```text
- 내가 이해하고 싶은 질문
- 직접 붙여넣은 글 요약
- 내가 작성한 문제 상황
- 내 코드 오류
- 내 연습 녹음에 대한 메모
- 내가 정리한 논문 요약
- 내가 해결하고 싶은 과제 설명
```

## 4. 지점 학습 메뉴 구조

지점 안에서 학습 콘텐츠를 소화하기 위한 사용자-facing 메뉴는 4단계로 단순화한다.

```text
지점 학습 메뉴
├─ 관찰
├─ 반복하기
├─ 결과물 기록
└─ 완료확인
```

이 4단계는 기존 지점 학습흐름의 세부 요소를 사용자에게 부담이 적은 메뉴로 묶은 구조다.

---

## 5. 관찰

### 5.1 목적

관찰은 학습 콘텐츠를 단순히 보는 단계가 아니라, 이 자료를 통해 무엇을 할 수 있어야 하는지 찾는 단계다.

```text
관찰
= 학습 콘텐츠 또는 학습 대상을 보고
  목표와 필요한 스킬을 발견하는 단계
```

### 5.2 포함 기능

```text
- 콘텐츠 보기 / 외부 콘텐츠 열기
- 핵심 내용 메모
- 목표 찾기
- 스킬 찾기
- 루미 안내
```

### 5.3 목표 찾기

사용자는 이 지점에서 만들거나 수행하거나 설명할 수 있는 구체 결과를 찾는다.

예시:

```text
- 독자 정의 문장 1개 만들기
- F코드 전환 녹음하기
- Todo 앱 기능 하나 구현하기
- 작은 파우치 v1 만들기
- 영어 카페 주문 대화 녹음하기
- 개념을 내 말로 설명하기
```

### 5.4 스킬 찾기

스킬은 목표 달성을 위한 하위 행동 또는 사고 단위다.

스킬 후보 출처는 다음과 같다.

```text
1. 크리에이터가 제시한 스킬 후보
2. 콘텐츠 기반 AI 보완 스킬
3. 학습자가 직접 추가한 스킬
```

크리에이터가 제시한 스킬은 후보이며, 학습자가 선택, 수정, 추가한 스킬이 실제 학습진행 스킬이 된다.

---

## 6. 반복하기

### 6.1 목적

반복하기는 선택한 스킬을 실제 행동으로 바꾸고, 반복 과정과 변화를 기록하는 단계다.

```text
반복하기
= 선택한 스킬을 반복 방법에 따라 실행하고,
  필요하면 과정과 중간 결과를 기록하는 단계
```

### 6.2 포함 기능

```text
- 반복할 스킬 선택
- 반복 방법 확인
- 스킬 유형별 기록 템플릿 선택
- 반복 기록 작성
- 막힌 점 기록
- 질문하고 해답찾기
- 필요 시 중간 결과 저장
- 스킬별 자기평가
```

### 6.3 스킬별 자기평가

각 스킬마다 반복 후 짧은 자기평가를 남길 수 있다.

```text
스킬별 자기평가
├─ 이번에 나아진 점
├─ 더 반복해야 하는 점
├─ 새롭게 발견한 필요 스킬
└─ 다음 반복 방법
```

---

## 7. 스킬 유형별 기록 템플릿 선택

### 7.1 도입 목적

모든 스킬을 같은 입력 폼으로 기록하면 사용자가 무엇을 적어야 할지 헷갈릴 수 있다.

따라서 스킬 유형에 따라 기록 템플릿을 선택할 수 있게 한다.

```text
스킬 유형별 기록 템플릿
= 스킬 성격에 맞게 반복 기록 필드를 다르게 제공하는 구조
```

### 7.2 기본 원칙

1. 스킬 기록은 지도 노드가 아니라 학습 진행 데이터다.
2. 기본 템플릿은 항상 제공한다.
3. 모바일에서는 축약 템플릿을 우선 제공한다.
4. 필요할 경우 확장 템플릿으로 전환할 수 있다.
5. 템플릿은 강제값이 아니라 추천값이다.
6. 학습자는 템플릿을 바꾸거나 직접 기록할 수 있어야 한다.

### 7.3 기존 Skill Note 기본 템플릿 계승

기존 Skill Note 시스템의 기본 템플릿은 다음 구조를 가진다.

```text
스킬:
목표물 버전:
어려웠던 점:
막힌 점:
궁금한 점:
시도한 해결 방법:
발견한 점:
다음 반복 목표:
첨부:
```

모바일 축약 템플릿은 다음과 같다.

```text
스킬:
어려웠던 점 또는 막힌 점:
다음 반복 목표:
```

LearnCosmos에서는 이 구조를 유지하되, 스킬 유형별 템플릿으로 확장한다.

### 7.4 스킬 유형 후보

초기 스킬 유형은 다음 정도로 시작한다.

```text
1. 이해형 스킬
2. 문제풀이형 스킬
3. 제작형 스킬
4. 수행형 스킬
5. 분석/진단형 스킬
6. 탐구/질문형 스킬
7. 디버깅/개선형 스킬
```

### 7.5 템플릿 A: 이해형 스킬

사용 예:

```text
개념 이해, 글 읽기, 영상 강의 이해, 논문 읽기, 이론 정리
```

기록 필드:

```text
스킬:
이해한 핵심 내용:
내 말로 설명하기:
헷갈린 점:
예시로 설명해보기:
다음에 다시 확인할 것:
첨부 / 참고 링크:
```

### 7.6 템플릿 B: 문제풀이형 스킬

사용 예:

```text
수학 문제풀이, 자격증 문제, 오답 정리, 논리 문제, 독해 문제
```

기록 필드:

```text
스킬:
풀어본 문제 / 과제:
처음 막힌 부분:
내가 시도한 풀이:
해설 또는 정답과 비교한 점:
오답 원인:
다음 풀이 전략:
첨부:
```

### 7.7 템플릿 C: 제작형 스킬

사용 예:

```text
코딩, 글쓰기, 디자인, 만들기, 공예, 영상 제작, 앱 제작
```

기록 필드:

```text
스킬:
이번에 만든 것:
버전:
어려웠던 점:
수정한 부분:
좋아진 점:
다음 개선 목표:
첨부 / 링크:
```

### 7.8 템플릿 D: 수행형 스킬

사용 예:

```text
운동, 악기, 말하기, 발음, 발표, 연기, 실습 수행
```

기록 필드:

```text
스킬:
반복 횟수 / 시간:
수행 결과:
몸 감각 / 소리 / 자세 / 흐름:
어려웠던 점:
좋아진 점:
다음 반복 목표:
녹음 / 영상 / 사진 첨부:
```

### 7.9 템플릿 E: 분석/진단형 스킬

사용 예:

```text
작품 분석, 코드 리뷰, 오류 원인 분석, 사례 분석, 자기 결과물 진단
```

기록 필드:

```text
스킬:
분석 대상:
기준 또는 비교 대상:
발견한 문제:
원인 추정:
개선 방향:
다음 확인할 것:
첨부:
```

### 7.10 템플릿 F: 탐구/질문형 스킬

사용 예:

```text
궁금증 정리, 연구 질문 만들기, 자료 비교, 논문 탐색, 원인 탐구
```

기록 필드:

```text
스킬:
탐구 질문:
찾아본 자료:
현재까지의 답:
아직 모르는 점:
다음에 확인할 자료:
내 결론:
첨부 / 링크:
```

### 7.11 템플릿 G: 디버깅/개선형 스킬

사용 예:

```text
코드 에러 해결, 글 수정, 작품 개선, 자세 교정, 반복 개선
```

기록 필드:

```text
스킬:
문제 상황:
시도한 해결 방법:
결과:
남은 문제:
새롭게 알게 된 점:
다음 수정 목표:
첨부 / 실행 결과:
```

### 7.12 템플릿 선택 UX

스킬을 선택하면 루미가 적절한 템플릿을 추천한다.

예시:

```text
루미:
이 스킬은 직접 만들어보는 연습에 가까워요.
제작형 기록 템플릿으로 시작해볼까요?

[제작형으로 기록하기]
[다른 템플릿 선택]
[간단히 기록하기]
```

모바일에서는 먼저 축약 필드를 보여준다.

```text
간단 기록
- 어려웠던 점 또는 막힌 점
- 이번에 나아진 점
- 다음 반복 목표
```

필요할 때 `자세히 기록하기`를 눌러 유형별 확장 템플릿을 연다.

## 8. 결과물 기록

### 8.1 목적

결과물 기록은 최종 학습목표에 맞는 산출물 또는 증거를 남기는 단계다.

```text
결과물 기록
= 이 지점에서 배운 것을 결과물로 남기는 단계
```

### 8.2 결과물 유형

```text
- 내 말로 설명하기
- 파일 / 이미지 첨부
- 링크 등록
- 코드 기록
- 녹음 / 영상 기록
- 문제풀이 / 체크리스트
- 제작물 또는 수행 기록
- 기타
```

`내 말로 설명하기`는 보조 질문이 아니라 결과물 유형 중 하나로 본다.

### 8.3 안내 문구

```text
최종 결과물을 남겨주세요.
파일이나 링크를 올려도 되고,
이번에 배운 내용을 내 말로 설명해도 좋아요.
```

---

## 9. 완료확인

### 9.1 목적

완료확인은 질문을 많이 던지는 단계가 아니라, 사용자가 이번 지점을 반복할지 완료할지 판단하는 단계다.

### 9.2 완료확인 흐름

```text
최종 결과물 등록
→ 결과물 자기평가
→ 반복 / 완료 선택

반복 선택
→ 보완할 점
→ 추가 스킬
→ 목표 연결 확인

완료 선택
→ 학습을 통해 좋아진 점
→ 지점 완료
```

### 9.3 반복 또는 완료 선택

```text
이번 학습을 어떻게 할까요?

○ 더 반복할래요
○ 완료할래요
```

### 9.4 반복을 선택하는 경우

반복을 선택하면 다음 질문을 보여준다.

```text
보완해야 할 점은 무엇인가요?
```

```text
추가해야 할 스킬이 있나요?

○ 없어요
○ 있어요
```

`있어요` 선택 시 추가로 필요한 스킬을 입력한다.

```text
최종 결과물이 이번 학습의 목표와 연결되어 있나요?
아니면 목표를 다시 정할까요?

○ 목표와 연결되어 있어요
○ 목표를 조금 수정해야 해요
○ 목표를 다시 정해야 해요
```

### 9.5 완료를 선택하는 경우

완료를 선택하면 다음 질문만 보여준다.

```text
이번 학습을 통해 좋아진 점은 무엇인가요?
```

예시:

```text
- 개념을 내 말로 설명할 수 있게 되었어요.
- 직접 따라 해보면서 막히는 부분을 알게 되었어요.
- 결과물을 만들면서 필요한 스킬을 확인했어요.
```

## 10. 루미 안내 기준

루미는 명령자가 아니라 안내자다.

상황별 예시는 다음과 같다.

```text
코스 처음 진입:
이 행성에는 여러 지역이 있어요.
처음에는 첫 지역의 첫 지점부터 시작해볼까요?

마지막 학습 지점 있음:
지난번에 여기서 멈췄어요.
바로 이어서 작은 행동 하나만 해볼까요?

기록이 빠진 지점 있음:
이 지점은 학습은 했지만 기록이 아직 없어요.
한 줄만 남겨도 다음에 이어가기 쉬워요.

결과물 필요:
이 지점은 결과물이 있어야 완료할 수 있어요.
작은 캡처나 링크, 또는 내 말로 설명하기라도 남겨볼까요?

복습 필요:
이 지점을 완료한 지 며칠 지났어요.
지난 질문 하나만 다시 확인해볼까요?
```

## 13. 스킬 종류별 기록 템플릿 v1

### 13.1 기본 원칙

스킬 종류별 기록 템플릿은 저장 필드를 다르게 만드는 구조가 아니다.

모든 스킬 기록은 공통 기준 필드 9개를 사용하고, 스킬 종류별 템플릿은 사용자가 쉽게 입력할 수 있도록 질문 문구와 선택 칩을 다르게 제공하는 화면 양식이다.

```text
저장 필드 = 공통 9개로 고정
입력 템플릿 = 스킬 종류별 안내 문구와 선택 칩만 변경
```

공통 기준 필드는 다음과 같다.

```text
1. 스킬명
2. 스킬설명
3. 진행회차
4. 한 일
5. 좋아진 점
6. 더 연습할 점
7. 새로 필요한 것
8. 다음 행동
9. 남길 자료
```

초기 스킬 종류는 다음 7종으로 시작한다.

```text
1. 이해·설명형
2. 문제풀이형
3. 제작형
4. 수행·연습형
5. 분석·진단형
6. 탐구·조사형
7. 디버깅·개선형
```


#### 더 연습할 점 선택 칩

```text
[원인 찾기가 어려워요]
[해결 방법을 모르겠어요]
[수정해도 다시 문제가 생겨요]
[비교가 어려워요]
[테스트가 부족해요]
[없어요]
[직접 입력]
```

#### 새로 필요한 것 선택 칩

```text
[없어요]
[오류 메시지 읽기가 필요해요]
[기초 개념이 필요해요]
[테스트 방법이 필요해요]
[비교 기준이 필요해요]
[직접 추가]
```

#### 남길 자료

```text
[수정 전/후 비교]
[에러 메시지]
[실행 결과]

[코드]
[이미지]
[없어요]
```

### 13.9 최종 기준

스킬 종류별 템플릿은 7종으로 시작한다.

```text
1. 이해·설명형
2. 문제풀이형
3. 제작형
4. 수행·연습형
5. 분석·진단형
6. 탐구·조사형
7. 디버깅·개선형
```

모든 템플릿은 공통 기준 필드 9개를 사용한다.

```text
스킬명
스킬설명
진행회차
한 일
좋아진 점
더 연습할 점
새로 필요한 것
다음 행동
남길 자료
```

템플릿별 차이는 저장 구조가 아니라, 사용자가 쉽게 입력하도록 돕는 선택 칩과 안내 문구의 차이다.

## 14. 최종 정리

```text
지점 학습 UX는 관찰, 반복하기, 결과물 기록, 완료확인의 4단계로 구성한다.

관찰 단계에서는 목표와 필요한 스킬을 찾는다.
반복하기 단계에서는 스킬별 반복 방법과 기록 템플릿을 선택하고, 반복 과정과 개선점을 기록한다.
결과물 기록 단계에서는 최종 학습목표에 맞는 결과물을 남기며, 내 말로 설명하기도 결과물로 인정한다.
완료확인 단계에서는 반복 또는 완료를 선택하고, 반복 시 보완점과 추가 스킬을 확인하며, 완료 시 학습을 통해 좋아진 점을 기록한다.
```
