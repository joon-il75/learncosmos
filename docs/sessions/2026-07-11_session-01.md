# 2026-07-11 session-01

## 주제

서버 사양 및 운영 구성 문서화

## 사용자 요청

사용자는 서버 사양과 시스템 구성이 문서화되어 있는지 확인한 뒤, 추가로 서버 사양도 문서화하고 마감작업까지 진행하자고 요청했다.

## 확인 내용

기존 문서에는 앱 시스템 구성, 런타임 라이브러리, nginx 템플릿, 배포 포트 기준이 일부 문서화되어 있었다. 하지만 운영 서버의 실제 CPU, 메모리, 디스크, 커널, 설치 런타임, listen 포트 같은 서버 사양 인벤토리는 별도 문서로 정리되어 있지 않았다.

이번 확인에서 파악한 주요 서버 기준은 다음과 같다.

```text
OS: Ubuntu 24.04.4 LTS
Kernel: Linux 6.8.0-84-generic
Virtualization: KVM
CPU: 2 vCPU, AMD EPYC 9454P
Memory: 7.8 GiB
Swap: 없음
Disk: 50G ext4 root, 74% 사용
Public IP: 175.45.200.17
Domain: learncosmos.co.kr, www.learncosmos.co.kr
Frontend port: 3001
Backend port: 8081
PostgreSQL: 127.0.0.1:5432
Redis: 127.0.0.1:6379
```

## 작업 내용

- `docs/wiki/operations/server-inventory.md`를 새로 작성했다.
- 문서에는 서버 기본 정보, 하드웨어/가상 자원, 런타임 버전, 네트워크/포트, nginx/HTTPS 기준, 배포/실행 기준, 백업 기준, 재확인 명령을 정리했다.
- `docs/wiki/00_INDEX.md`의 operations 섹션에 서버 인벤토리 문서를 연결했다.
- `docs/changelog.md`에 서버 사양 및 운영 인벤토리 문서화 이력을 추가했다.

## 운영상 주의

- hostname은 아직 `learnweaver`로 남아 있다. 사용자-facing 브랜드와 저장소 기준은 LearnCosmos지만, hostname 변경은 SSH, 서비스, 운영 스크립트에 영향을 줄 수 있어 별도 계획 없이 변경하지 않는다.
- 루트 디스크 사용량이 74%라 서버 이미지 백업이나 대용량 dump 전에 여유 공간 확인이 필요하다.
- swap이 없어 빌드와 대용량 처리 작업에서 메모리 압박이 생길 수 있다.
- `9000`, `111` 포트가 listen 중이나 LearnCosmos 공식 문서상 용도가 명확하지 않아 별도 확인 전 중지하지 않는다.

## 검증

- 문서 변경 후 `git diff --check`를 실행한다.

## 배포/재시작

문서만 변경하는 작업이므로 배포와 재시작은 하지 않는다.

## 추가 작업: 서버 초기화 전 표준 백업

사용자는 Git에 소스를 백업했으니 서버를 초기화하거나 삭제할 계획이라고 말했다. 확인 결과 당시에는 Git에 올라가지 않은 변경/미추적 파일이 남아 있었으므로, 즉시 삭제는 위험하다고 판단했다. 이후 사용자가 표준 백업 처리를 요청했다.

진행한 표준 백업은 다음과 같다.

```text
Git 소스 백업 커밋: 8a66fd9 chore: backup current learncosmos source
원격: git@github.com:joon-il75/learncosmos.git main
로컬 백업 디렉터리: /home/cosmos/archive/learncosmos-standard-backups/20260711-183556
압축 백업 파일: /home/cosmos/archive/learncosmos-standard-backups/20260711-183556.tar.gz
SHA-256: a56e441cc32f84ef110c73a8f68a723e3d1b2a8cfe44bd43e4267cf2ba8b5fef
```

백업에 포함한 항목은 다음이다.

```text
- PostgreSQL custom dump: db/learncosmos-db.dump
- PostgreSQL schema-only dump: db/learncosmos-schema.sql
- Redis RDB: redis/redis-dump.rdb
- Runtime env: config/run__learncosmos__backend.env
- Bootstrap env: config/etc__learncosmos__backend.env
- nginx site config: etc-nginx/learncosmos
- Git bundle: git/learncosmos-main.bundle
- frontend/backend 로그 일부
- 백업 메타데이터, 파일 목록, SHA-256 체크섬
```

검증 결과는 다음과 같다.

```text
npx tsc --noEmit: 통과
go build ./...: 통과
git diff --check: 통과
git bundle verify: 통과
pg_restore --list: 통과
tar -tzf: 통과
git status: main...origin/main, clean
```

주의할 점은 다음이다.

- `/etc/letsencrypt/live/learncosmos.co.kr` 인증서 경로는 현재 권한/접근 문제로 백업하지 못했다.
- 백업 tar.gz는 아직 같은 서버의 `/home/cosmos/archive/` 아래에 있다. 서버를 실제 삭제하기 전에는 반드시 다른 PC 또는 외부 스토리지로 옮겨야 한다.
- 백업에는 env 파일과 DB dump가 포함되어 있으므로 외부로 옮길 때 공개 저장소나 공유 폴더에 올리면 안 된다.
