## 2026-07-04 learncosmos.co.kr 전환 준비

- 사용자는 `learncosmos.co.kr`을 기준 서비스로 올리는 1번 안전 전환을 선택했다.
- 공인 IP 기준은 `175.45.200.17`로 확인했다.
- 현재 확인 결과 `www.learncosmos.co.kr`은 `175.45.200.17`로 보이나, 루트 `learncosmos.co.kr`은 아직 `118.67.131.217`로 확인된다.
- 기존 `3000/8080` 서비스는 떠 있지 않고, LearnCosmos `3001/8081`은 로컬 smoke에서 정상이다.
- nginx는 현재 `dev.learnweavr.com` 등을 `3001/8081`로 proxy하고 있다.
- cosmos 계정은 sudo 그룹에 있으나 passwordless sudo가 아니므로 `/etc/nginx` 수정과 certbot 실행은 이 세션에서 직접 수행하지 못했다.
- 대신 `ops/nginx/learncosmos-http.conf`, `ops/nginx/learncosmos-ssl.conf.template`, `scripts/ops/enable-learncosmos-domain.sh`를 준비했다.

## 2026-07-04 learncosmos.co.kr DNS 검사 보강

- whois.co.kr 화면상 루트 도메인과 `www` A 레코드는 모두 `175.45.200.17`로 저장되어 있었다.
- `dig @ns1.whoisdomain.kr`, `@ns2`, `@ns3`, `@ns4` 직접 조회 결과도 모두 루트 도메인을 `175.45.200.17`로 응답했다.
- 일반 resolver/getent는 여전히 루트 도메인을 `118.67.131.217`로 볼 수 있어, 로컬 캐시 때문에 전환 스크립트가 과도하게 멈추는 문제가 있었다.
- `scripts/ops/enable-learncosmos-domain.sh`를 권한 네임서버 직접 조회 우선 방식으로 보강했다.
- 실제 nginx/certbot 전환은 아직 root 권한으로 실행하지 않았다.

## 2026-07-04 learncosmos.co.kr HTTPS 전환 완료

- 사용자가 root 권한으로 `scripts/ops/enable-learncosmos-domain.sh`를 실행했다.
- certbot은 `learncosmos.co.kr`과 `www.learncosmos.co.kr` 인증서 발급 및 nginx 배포를 성공적으로 완료했다.
- 인증서 저장 경로는 `/etc/letsencrypt/live/learncosmos.co.kr/fullchain.pem`, 키 경로는 `/etc/letsencrypt/live/learncosmos.co.kr/privkey.pem`이다.
- 스크립트 마지막 일반 `curl`은 로컬 resolver가 루트 도메인을 이전 IP로 보는 문제 때문에 실패했다.
- `curl --resolve learncosmos.co.kr:443:175.45.200.17 https://learncosmos.co.kr/`와 `www` 기준 강제 확인은 모두 HTTPS `200 OK`였다.
- 전환 스크립트의 최종 smoke check를 `--resolve` 기반으로 보강했다.

## 2026-07-04 새 레포 소스 이식과 공개 도메인 정리

- 현재 프론트 프로세스가 백업 폴더의 삭제된 standalone 경로에서 실행 중임을 확인했다.
- 백업 `frontend/`와 `backend/`를 새 레포로 이식하되 환경파일, 빌드 산출물, runtime storage, 빌드 바이너리는 제외했다.
- 최초 backend 이식 시 `backend/cmd/server/`가 바이너리 제외 패턴과 함께 빠진 것을 확인하고 별도로 복원했다.
- 프론트 공개 URL 기준을 `https://learncosmos.co.kr`로 정리하고 sitemap/robots/llms/HTML 메타데이터를 확인했다.
- `deploy-frontend.sh`가 기존 `3001` PID를 `lsof`로 잡지 못해 old process가 유지되는 문제를 확인했고, `fuser`/`ss` fallback을 추가했다.
- `npx tsc --noEmit`, `go build ./...`, `deploy-frontend.sh`, `deploy-backend.sh`를 통과했다.
- 최종 확인: frontend `:3001` PID는 새 레포 `.next/standalone`, backend `:8081` PID는 새 레포 `backend`에서 실행 중이다.
