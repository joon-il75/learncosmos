## 7. 추가 논의: 320px 모바일 햄버거 메뉴

320px 모바일 첫 화면 기준으로 햄버거 메뉴는 필요하다고 판단했다. 다만 햄버거 메뉴는 학습 행동의 중심이 아니라 전체 이동과 계정 확인을 위한 보조 서랍으로 둔다.

첫 화면에 직접 노출할 핵심 행동은 다음으로 제한한다.

```text
- 이어서 탐험하기
- 새 별 만들기
- 선택한 별 상세
- 오늘의 추천 항로
```

햄버거 메뉴에는 사용자 정보 블록을 상단에 둔다. 로그인 상태에서는 닉네임, 이메일 또는 display_id, AI 포인트 요약을 보여주고, 비로그인 상태에서는 Login 버튼과 짧은 안내를 보여준다. Logout은 메뉴 하단에 둔다.

사용자 정보는 메뉴의 컨텍스트로 보고, 로그인/로그아웃은 메뉴 기능으로 본다.

## 8. 추가 논의: 라이트 코스모스 색감

Galaxy Map의 전체 색감은 현재 `www.learncosmos.co.kr`의 밝은 LearnCosmos 톤을 유지한다. 검은 우주가 아니라 흰색과 밝은 보라색 성운 위에 은하가 얹힌 라이트 코스모스 화면으로 표현한다.

색감 기준은 다음과 같다.

```text
기본 바탕: 흰색 / 밝은 민트 / 밝은 하늘색
성운: 연한 보라색 / 라벤더 / 하늘색
별: 상태별 민트, 블루, 보라, 골드 광채
텍스트: 딥 네이비 / 청록 계열
CTA: 기존 민트/블루 계열
추천 항로: 밝은 보라색 또는 블루-퍼플 연결선
```

320px 모바일에서는 성운과 은하 효과를 과하게 쓰지 않고, 선택한 별과 이어서 탐험하기 CTA의 가독성을 우선한다. 모바일 기본 구현에서는 무거운 bloom 후처리를 사용하지 않고, 낮은 불투명도와 제한된 별 개수로 밝은 우주감을 만든다.

## 10. 보강: 공개 홈 기존 랜딩 제거와 넓은 모바일 기반 화면 적용

처음 구현한 320px Galaxy Map MVP는 로그인 후 `/dashboard`의 phone layout에만 적용되어 있었다. 사용자가 확인한 `www.learncosmos.co.kr/`는 공개 홈이므로 새 화면이 보이지 않았다.

이후 공개 홈에도 `PublicCosmosMobileFirstView`를 추가했으나, 사용자는 기존 랜딩을 유지하는 방식이 아니라 기존 랜딩을 삭제하고 모바일 레이아웃에서 화면을 넓혀 다시 잡는 방향을 요청했다. 이에 따라 공개 홈에서는 기존 긴 랜딩 여정, 소개 섹션, 알림 배너 렌더를 제거하고, 모바일 기준 라이트 코스모스 학습별 지도를 단일 첫 화면으로 사용한다.

구현 기준은 다음과 같다.

```text
- 320px 모바일에서 출발한다.
- 같은 화면을 최대 720px 폭까지 넓혀 태블릿/데스크톱에서도 유지한다.
- 공개 홈 첫 화면은 Lumi Route, 밝은 코스모스 별 지도, 새 별 생성 입력, 예시 주제 칩으로 구성한다.
- 기존 소개 영상/문서/AI 포인트/플랫폼 뉴스 랜딩 여정은 공개 홈 렌더에서 제외한다.
```

검증 결과는 다음과 같다.

```text

deploy-frontend.sh: 통과, frontend 3001 포트 재시작 확인
```

브라우저에서 이전 화면이 계속 보이면 정적 캐시 또는 브라우저 캐시일 수 있으므로 강력 새로고침이 필요할 수 있다.

## 11. 보강: canvas 기반 라이트 코스모스 효과

사용자가 `cosmos.codeghost.cloud` 같은 효과가 보이지 않는다고 지적했다. 기존 공개 홈 구현은 밝은 우주 분위기를 CSS로 표현한 정적 지도에 가까웠고, 사용자가 기대한 단일 캔버스 기반 별/연결선/성운 효과와는 거리가 있었다.

이에 따라 `PublicCosmosMobileFirstView`의 지도 영역에 실제 `canvas` 레이어를 추가했다. 캔버스는 다음 요소를 그린다.

```text
- 밝은 보라색 성운 그라디언트
- 은하 중심과 흐르는 먼지 입자
- 학습별 샘플 데이터 기반 별 위치
- 추천 학습 경로 연결선
- 활성 별과 다음 추천 별의 링/광채
```

구현은 Three.js 대신 Canvas 2D로 진행했다. 이유는 공개 홈 첫 화면에서 모바일 성능과 로딩 무게를 우선하기 위해서다. 추후 실제 학습 데이터와 확대/줌 인터랙션이 붙는 단계에서는 Three.js/WebGL 맵으로 확장할 수 있다.

검증 결과는 다음과 같다.

```text
npx tsc --noEmit: 통과
git diff --check: 통과
deploy-frontend.sh: 통과, frontend 3001 포트 재시작 확인
curl HTML 확인: <canvas>, Lumi Route, 하나의 학습별에서 시작하세요, 새 별 문구 포함
```

Playwright 라이브러리는 설치되어 있으나 Chromium 브라우저 바이너리가 서버에 없어 실제 캔버스 픽셀 검사는 보류했다. 브라우저에서 육안 QA를 진행할 때는 320x568, 390x844, 720px 폭 기준으로 별/선/카드 겹침을 확인해야 한다.

## 12. 구현: Three.js/WebGL, Raycaster, 카메라 줌 전환

사용자가 Three.js/WebGL, 카메라 줌, Raycaster 클릭 전환을 붙이자고 요청했다. 이에 따라 공개 홈의 `PublicCosmosMobileFirstView` 지도 영역을 Canvas 2D 기반 구현에서 Three.js/WebGL 기반 `ThreeCosmosMap`으로 전환했다.

구현 내용은 다음과 같다.

```text
- THREE.Scene / PerspectiveCamera / WebGLRenderer 구성
- THREE.Points로 은하 입자 배경 구성
- THREE.Sprite로 학습별 샘플 데이터 렌더링
- THREE.LineSegments로 추천 항로 연결선 렌더링
- Raycaster pointerdown으로 별 클릭 감지
- 선택한 별로 카메라 target을 이동해 줌인 전환
- 선택한 별 이름을 하단 패널과 입력값에 반영
- prefers-reduced-motion 대응 및 renderer pixelRatio 제한
```

`gsap`은 추가하지 않았다. 초기 공개 홈 MVP에서는 직접 `Vector3.lerp` 보간으로 카메라 전환을 구현해 의존성과 번들 무게를 줄였다. 향후 복잡한 시퀀스 전환이 필요해지면 `gsap` 추가를 검토한다.

검증 결과는 다음과 같다.

```text
npm install three: 통과
npm install --save-dev @types/three: 통과
npx tsc --noEmit: 통과
git diff --check: 통과
deploy-frontend.sh: 통과, frontend 3001 포트 재시작 확인
curl -I https://www.learncosmos.co.kr/: 200 OK
curl HTML 확인: Lumi Route, 하나의 학습별에서 시작하세요, 선택한 학습별, 새 별 문구 포함
```

서버에는 Playwright Chromium 바이너리가 없어 WebGL 캔버스 픽셀 검사는 보류했다. 브라우저 QA에서는 320x568, 390x844, 720px 폭에서 WebGL canvas가 비어 있지 않은지, 별 클릭 시 선택 별 문구와 입력값이 바뀌고 카메라가 해당 별로 줌인하는지 확인해야 한다.

## 13. 구현: 공개 홈 탑 메뉴 제거와 햄버거 유지

판단 기준은 다음과 같다.


## 15. 구현: 공개 홈 초기 은하 조감도 상태

사용자가 첫 진입 시 어떤 별도 선택한 상태가 아니므로 은하 조감도처럼 보여야 한다고 요청했다. 이에 따라 공개 홈의 초기 상태를 특정 학습별 선택 상태에서 선택 없음 상태로 변경했다.

구현 기준은 다음과 같다.

```text
- 첫 진입: selectedLabel = null
- 카메라: 은하 전체 조감도 위치
- 패널: 특정 별 이름 대신 조감도 안내 문구 표시
- 별 클릭: Raycaster로 선택 후 해당 별로 카메라 줌인
- 배경 클릭: 선택 해제 후 조감도 복귀
- 예시 주제 칩: 별 선택이 아니라 입력값 보조로 동작
```

검증 결과는 다음과 같다.

```text
npx tsc --noEmit: 통과
```

## 16. 구현: 공개 홈 은하 시각 강화

사용자가 현재 화면에서 은하 느낌이 약하다고 지적했다. 기존 Three.js 장면은 학습별 Sprite와 연결선은 있었지만, 은하의 핵심 시각 요소인 중심핵, 나선팔 밀도, 외곽 먼지층이 부족했다.

개선 내용은 다음과 같다.

```text
- 중심핵 Sprite 추가
- 3중 나선팔 입자층 추가
- 외곽 haze 입자층 추가
- 은하 중심부 색상과 밀도 강화
- 초기 조감도에서 학습별 라벨 투명도 낮춤
- 맵 높이를 334px에서 384px로 확장
- 밝은 보라색/하늘색 성운 대비 강화
```

검증 결과는 다음과 같다.

## 17. 구현: 은하 우선 구조와 코스 별 특수 효과

사용자가 참고 사이트처럼 은하 우선으로 재구성하고, 임의의 별들이 은하를 구성한 뒤 그 안에 학습별 맵을 구현해야 한다고 정리했다. 또한 클릭되는 별, 즉 코스가 생성된 별은 특별한 효과를 가져야 한다고 요청했다.

구현 내용은 다음과 같다.

```text
- 배경 별밭 createBackgroundStarfield 추가
- 외곽 haze 나선팔 레이어 추가
- 메인 나선팔 galaxy 레이어 추가
- 중심부 coreStars 레이어 추가
- 중심핵 Sprite 유지
- 학습별 별 위치를 은하 나선팔 좌표계 안으로 이동
- Course Star에 후광 Sprite 추가
- Course Star에 궤도 Ring Sprite 추가
- Course Star 선택 시 링 회전, 광채, 크기 강조
```

이제 시각 구조는 다음 순서가 된다.

```text
1. 임의의 수천 개 별이 은하를 구성
2. 학습별은 은하 안의 특별한 Course Star로 배치
3. 기본 조감도에서는 은하 구조가 먼저 보임
4. 사용자가 Course Star를 클릭하면 라벨과 카메라 줌이 활성화
```

검증 결과는 다음과 같다.

```text

deploy-frontend.sh: 통과, frontend 3001 포트 재시작 확인
```
